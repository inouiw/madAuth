Self-hostable authentication

An open-source alternative to Cognito and Auth0. Run the madAuth server in your own cloud account and add a ready-made login dialog to any web app.

Try the demo Get started

Sign-in methods

Google (One Tap / FedCM or redirect), GitHub, any OpenID Connect provider such as GitLab, Keycloak or Okta, e-mail & password with confirmation and password reset, passwordless e-mail links, passkeys, and an authenticator app or SMS codes as a second factor. Users can have several methods, and you decide which sign in on their own. Users make API keys for the scripts that call your API in their name.

Any framework

The login UI is a standard web component: plain HTML, React, Angular, Vue, Svelte or Capacitor.

Small in the browser

The login dialog with every sign-in method adds about 55 kB (gzipped) to your app. With a login screen of your own, the client alone is about 20 kB.

Your infrastructure

Node, Docker, AWS Lambda or Azure Functions, with SQLite, Postgres, DynamoDB or a database of your own. Your users stay in your database.

Keys outside the server

On AWS, the signing, hashing and encryption keys stay in AWS KMS and never leave it: someone who breaks into the server can't take them away. The AWS template creates and rotates them.

Secure by default

Failed sign-ins are slowed down per account, answers don't reveal who has an account, and adding or removing a sign-in method needs a sign-in within the last two minutes.

Add it to your app

npm install @madauth/web @madauth/server
npx @madauth/server init
